# Review: S5-commands — precision
Skipped as already decided: D7 (`storage_full` in `SnapshotFailReason` and the message table), D6 (`snapshot.intervalTicks`), D11 (S1 body interfaces).

| # | Severity | Location | Problem | Exact fix |
|---|---|---|---|---|
| 1 | major | §7 fight table and §5 "Fields `!status` needs" | The option rows (`attack`, `shield`, `back_off`, ...) are applied to any `status.option`, with no guard on `status.layer`. S1 says `option` is only meaningful while `layer === "combat"`; a stale `attack` in layer `task` would print "fighting zombie" while the bot gathers. | Add to §7 above the table: "The option rows apply only when `status.layer === "combat"`. For layer `task` or `idle` the `{fight?}` segment is omitted unless `recovering` is true." |
| 2 | major | §7 "fresh info" vs D8 | Contradiction at the boundary: §7 uses `now - at < statusStaleTicks` (age 100 is hidden) while D8 says "older than 100 ticks is hidden" (age 100 is shown). | Use `now - at <= cfg.statusStaleTicks` in §7, §5 (`BotView.combat` comment) and the tests. |
| 3 | major | §4.8 step 3 | The `goto` destination for a home is `home.pos`, an integer block CORNER (§2). A bot sent to `(x, y, z)` stands on the block edge, and the executor's arrival tolerance can fail in the next block. | Replace with: "`dest = home ? { x: home.pos.x + 0.5, y: home.pos.y, z: home.pos.z + 0.5 } : { ...sender.pos }`". The same `+0.5` rule applies wherever S4/S1 convert `HomeRef.pos` to a walking target: add it to §2 as "walking target = block centre (x+0.5, y, z+0.5)". |
| 4 | major | §4.5 `all` vs `<bot>` | The cancel reason for dropping an own task differs without reason: `all` uses `cancel(rec, "preempted")`, `<bot>` says "cancel own task (dropped)" with no reason, `!recall` uses `"stopped"`. The reason selects the messages the runtime emits. | Use `cancel(rec, "stopped")` in both summon paths (replace `"preempted"` in `all`; add `"stopped"` to the `<bot>` live-idle/own-task line). |
| 5 | major | §4.7 `botRejoined` | "If that task is already complete (`delivered >= amount`) drop it silently" is defined only for gather. `GotoTask` and `DefendTask` have no `delivered`/`amount`, and defend never completes. | Replace with: "If `task.kind === "gather"` and `progress.delivered >= task.amount`: drop it silently. Every other task kind is re-assigned unchanged." |
| 6 | minor | §4.7 `botRejoined` | A `botRejoined` for a name that already has a LIVE record (duplicate or late event) is not covered; the text would create a second record. | Add: "If `s.bots` already has a record with `presence === "live"` and the same lowercase name, ignore the event and log `[colony] duplicate botRejoined <name>`." |
| 7 | minor | §3.3 `!home foo` | The error text hard-codes the prefix `!` (`Use !home or !home set.`) although the same row says the prefix comes from the `prefix` parameter. | Replace with `Unknown home action '{echo}'. Use {p}home or {p}home set.` (`{echo}` = `echo(token)`, `{p}` = prefix). |
| 8 | minor | §3.2 / §3.3 integer parsing | "whole number" is not defined: `+16`, `16.0`, `1e1`, `０` may be accepted or not. | Add: "`defendArg` accepts a token only if it matches `/^[0-9]+$/` and `minRadius <= Number(token) <= maxRadius`, else the radius error. The literal `stop` is compared with `token.toLowerCase() === "stop"`." |
| 9 | minor | §3.2 `build()` | The mapping from a parsed argument to its `Values` key is not stated for the new arg types (`defendArg`, `botOrAll`, `homeAction`), so `v.radius`, `v.stop`, `v.target` can be filled in more than one way. | Add: "`parseArg` sets: `defendArg` -> `values.stop = true` for `stop`, else `values.radius = n`; `botOrAll` -> `values.target`; `homeAction` -> `values.homeAction = "set"`; `count` -> `values.count` (existing)." |
| 10 | minor | §5 `BotView.id` | "non-live: `dismissed:${lowercaseName}`" also covers `leaving` and `rejoining` records, which still have a (soon invalid) entity id. | Replace the comment with: "`id` = the entity id for `live`, `leaving` and `rejoining` (rejoining: the OLD id); `dismissed:${lowercaseName}` only for `presence: "dismissed"`." |
| 11 | minor | §4.2 step 2, `DefendTask.center` | "exact, not floored" gives a Vec3 with fractions, but the examples print `defending 100 64 200 (r16)`. The rounding of `{pos}` is only implied by `fmtPos`. | Add: "`{pos}` in every defend string uses the existing `fmtPos` (which rounds as for goto). The task keeps the exact floats." If `fmtPos` floors, say so here; the builder must check `src/core/colony/messages.ts` and report a mismatch. |
| 12 | minor | §6 `equipNeed` article | The text does not say whether `{item}` keeps underscores, so `I need an iron_sword` and `I need an iron sword` are both valid readings, and a test cannot assert one string. | Add: "The item shown is `shortId(typeId)` with `_` replaced by a space (`iron sword`); the article is chosen from the first letter of that text." |
| 13 | minor | §4.4 timeout | A late `botDismissed` after the `leaving` timeout reverted the record to `live` and perhaps gave it a new task: the rule "remove the record ... create AbsentBot" then silently drops that task. | Add: "If the record has a task when a late `botDismissed` arrives, requeue it at the queue front (as `botRemoved` does) and send `botLeftRequeued` to the task issuer." |
