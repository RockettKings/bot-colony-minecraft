# Review: S4a-snapshot-data — completeness (pass 2)

Checked against `briefs/S4a.md` (items 1 to 8), PHASE3-SPEC §4/§5/§6, ROADMAP (snapshot exception, return and escape rules, "saved on every inventory change and on a timer"), API-MAP §D5 (lossy-item list and the "Rule for the snapshot code"), DECISIONS D6 to D10, D21, D26. All eight brief items are present: types with mainhand never stored, excluded list, pure codec with FNV-1a and migration stub, store with write-then-commit and byte accounting, capture/clear/apply with a per-slot cursor, triggers with the P4 argument and fallback, 13 config keys, 9 open questions. D31 has no item for S4a. The gaps below are an API-MAP rule that was not carried over, a loss that is never reported, and ownership and test holes.
