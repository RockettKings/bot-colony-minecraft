# Review: S1-stack-sensing — logic

| # | Severity (blocker/major/minor) | Location (§ / line) | Problem | Exact fix (replacement text, number, or decision) |
|---|---|---|---|---|
| 1 | blocker | §9.4 lava/drowning escalation (with D17 lavaEscapeTicks=20) | Escalation is measured from the reflex `since`. Reflex exit requires 20 consecutive clear ticks, so any reflex that ends normally has already lasted more than 20 ticks. Every lava or drowning reflex therefore reaches `now - since >= lavaEscapeTicks` and becomes an escape, killing the "reflex resolved it" path and spending a snapshot/escape on routine events. | Replace the escalation guard with: `if (mem.clearSince === undefined && now - since >= config.reflex.lavaEscapeTicks) beginEscape("lava")`. Same form for drowning with `drownEscapeTicks`. `clearSince` is set on the first clear tick and cleared on any hazard tick, so only continuous hazard of 20 ticks escalates. |
| 2 | blocker | §3.2 T10/T11 (CALM guard) | A `blocking_objective` threat (caged, avoid policy, `attackAllowed=false`) is counted by the CALM-hold guard, so the machine stays in CALM as long as the mob exists. The task never resumes: deadlock between CALM and TASK. | Change the T10 hold guard to `any(threat.relevance === "threatening_me")` only. Add `calmMaxWaitTicks = 600` (§10): after that many ticks in CALM, T11 fires regardless of remaining threats and the executor resumes with `avoid` policy for blocking_objective mobs. |
| 3 | major | §9.2 drowning trigger | The airFrac trigger does not require `headInWater`. If the air-supply unit is mis-scaled (R2 uncertainty) or stale, `airFrac <= drownAirFrac` holds permanently and the reflex locks on forever, since exit needs `airFrac > drownAirFrac`. | Trigger: `self.headInWater && airFrac !== undefined && airFrac <= config.reflex.drownAirFrac`. Exit: `!self.headInWater || airFrac === undefined || airFrac > drownAirFrac`, held for the 20-tick clear stretch. |
| 4 | major | §5.3/§5.4 `approaching` | `approaching` uses distance decrease, which includes the bot's own movement. A bot that walks toward a mob (task path, chase) marks the mob as approaching and escalates relevance to `threatening_me`, which causes the bot to "chase by walking" and fight things it merely walked toward. | Define `approaching = dist3(prev.entityPos, self.pos) - distance >= config.sense.approachMinDelta` (distance from the entity's previous position to the bot's current position minus the current distance, i.e. the entity's own displacement toward the bot). Add `approachMinDelta = 0.4` to §10. |
| 5 | major | §5.5/§6.2 provoked rule | A neutral mob whose `targetId === botId` (it is actively attacking the bot) is still classified neutral and never becomes provoked, so the bot takes hits without responding. | Add `\|\| (r.targetId === botId && !NEUTRAL_NEVER_HIT.has(r.typeId))` to the `provoked` predicate. NEUTRAL_NEVER_HIT mobs keep their current rule (never hit). |
| 6 | major | §3.6 `beginEscape` / `escapeAvailable` | `beginEscape` ignores `escapeBlockedUntil` and `escapeAvailable` is used in guards but never defined. A blocked escape (previous failed hand-off) can be retried immediately, producing an escape loop; the guard is untestable. | Define `escapeAvailable = !escapePending && now >= escapeBlockedUntil`. `beginEscape` begins with `if (!escapeAvailable) return false;` and every caller treats `false` as "no escape, stay in FIGHT/REFLEX". |
| 7 | major | §3.2 carry executor vs S5 `assign` effect (cross-spec) | On escape-rejoin the carry executor already owns the task. The S5 `assign` effect then installs a second executor for the same task id, so the task runs twice (double mining/placing, doubled item consumption). | Make `assign` idempotent: `if (executor?.taskId === task.id) return;` and state this in S1 §3.6 step "rejoin": rejoin restores the executor, it never re-emits `assign` for the same task id. |
| 8 | minor | §3.6 rejoin / invariant I3 | `frozenObjective` is never assigned on rejoin, so I3 (objective frozen across hand-off) is violated; the first relevance pass after rejoin uses an empty objective. | In the rejoin step add: `frozenObjective = snapshot.objective`, then clear it at HANDOFF to IDLE/TASK completion. |
| 9 | minor | §3.2 T17 | T17 sets `phase = "calm"` inside the reflex layer, which only owns REFLEX/exit. The phase value is later overwritten by the controller. | Move the phase assignment out of the reflex layer: T17 only emits `reflexExit`; the controller sets `phase = "calm"` on the next tick. |
| 10 | minor | §2.4 step 5 and private-state table | The private-state table omits `nextScanAt`, `prevDist` and `lastEatDecision`. Step 5 reads `objective` before it is built in step 6. | Add the three fields to the table with initial values `0`, `new Map()`, `undefined`. Reorder: build `objective` (step 6) before relevance (step 5), or rename so step 5 reads `frozenObjective ?? objective` from the previous tick and say so. |
| 11 | minor | §3.7 `onDeath` | `onDeath` does not reset breadcrumbs, `prevDist` or `escapeBlockedUntil`. After respawn, stale entries cause false `approaching` values and a stuck block. | Add to `onDeath`: `breadcrumbs.length = 0; prevDist.clear(); escapeBlockedUntil = 0;`. |
| 12 | minor | §9.3 warden reflex | The warden reflex has no maximum duration; a warden that stays within range keeps the bot in REFLEX forever (flee never completes). | Add `wardenReflexMaxTicks = 1200` to §10. After that, reflex hands off to `beginEscape("warden")`; if unavailable, resume the flee with a new `since`. |
| 13 | minor | §3.2 T1 wording | "Entering FIGHT when any threat is present" is ambiguous with relevance classes; T1 can be read as firing for `blocking_objective`. | Reword T1 guard to: `threat.relevance === "threatening_me" && threat.attackAllowed`. |
| 14 | minor | §5.3 `nearestCell` | Tie order for dy is unspecified; two cells at equal distance resolve nondeterministically, producing replay differences. | Add: "ties broken by smaller `abs(dy)`, then smaller x, then smaller z." |
